# 日事清用户信息采集 页面线框说明稿 / 交互稿文案

这份文档用于把 [`rishiqing-user-information-collection-prd.md`](/Users/sihuo/workspace/Product-Manager-Skills/research/wps-project-management/synthesis/rishiqing-user-information-collection-prd.md) 继续下沉到页面与交互层。

目标不是做高保真视觉稿，而是帮助产品、设计、前端先对齐：

- 哪些页面要做
- 每个页面的结构是什么
- 关键交互怎么走
- 每个状态要显示什么文案
- 什么地方应该温和，什么地方必须明确

---

## 1. 设计目标

### 用户侧目标

- 让用户感觉“系统在理解我”，而不是“系统在盘问我”
- 让用户在回答后立刻看到收益
- 降低首次进入产品的空白感和陌生感

### 业务侧目标

- 在不明显伤害激活的前提下收集最小必要信息
- 把采集结果即时用于推荐和 AI 输出
- 为后续模板推荐、首页分流、销售打标提供稳定入口

### 设计原则

- 问题短、选项清晰、每次只推进一步
- 每个问题都离用户的下一步更近，而不是离公司数据库更近
- 能单选就不开放输入，能渐进就不一次性采完
- 回答后必须立即给反馈，否则用户只会记住“又填了个表”

## 2. 页面总览

建议一期覆盖 4 个核心页面 / 触点：

1. 注册后 onboarding 引导页
2. onboarding 完成后的个性化结果页
3. AI 对话中的补采卡片
4. 模板中心触发采集弹层

二期扩展：

5. 首页个性化空状态 / 推荐模块
6. 销售 / 客成补录侧边栏

## 3. 页面 1：注册后 onboarding 引导页

### 页面目标

用 3 题在 10 秒内完成最小画像采集，并把用户送进更贴近自己的下一步。

### 推荐展示形式

- 全屏轻引导页，优先于小弹窗
- 单题单屏
- 顶部显示轻量进度，如 `1/3`
- 底部固定主按钮和次按钮

### 线框结构

```text
+--------------------------------------------------+
| Logo                              1/3            |
|                                                  |
|   标题：想先帮你把日事清调成更适合你的样子       |
|   说明：回答 3 个问题，我们会直接推荐合适模板    |
|                                                  |
|   问题标题                                       |
|   ○ 选项 A                                       |
|   ○ 选项 B                                       |
|   ○ 选项 C                                       |
|   ○ 选项 D                                       |
|   ○ 其他                                         |
|                                                  |
|                     [跳过]   [下一步]            |
+--------------------------------------------------+
```

### 文案建议

#### 页面总标题

`想先帮你把日事清调成更适合你的样子`

#### 页面辅助说明

`回答 3 个问题，我们会直接推荐适合你的模板和 AI 助手。`

说明：
- 这句比“完善资料”更好，因为它承诺了回报。
- 不建议使用“问卷”“信息采集”等词，会直接拉低意愿。

### 问题 1

#### 标题

`你希望先用日事清解决什么问题？`

#### 选项

- `管理项目`
- `管理团队任务`
- `做流程审批`
- `管理客户`
- `做 OKR / 目标管理`
- `其他`

#### 主按钮

- 未选择前：`下一步` 置灰
- 已选择后：`下一步`

#### 次按钮

`跳过`

### 问题 2

#### 标题

`你现在最大的困扰是什么？`

#### 选项

- `项目进度不可控`
- `任务经常拖延`
- `沟通很乱`
- `不清楚谁在负责`
- `不知道从哪开始`

#### 交互说明

- 一期建议单选，不建议多选
- 单选更利于完成率，也更利于系统马上给出“第一推荐”

### 问题 3

#### 标题

`你目前更接近哪种角色？`

#### 选项

- `老板 / 业务负责人`
- `项目经理`
- `团队负责人`
- `执行者`
- `其他`

### 可选问题 4

如果业务希望一期加入团队规模题，建议作为可选补充，不建议默认强制。

#### 标题

`你的团队大约有多少人？`

#### 选项

- `就我自己`
- `2-10 人`
- `11-50 人`
- `51 人以上`

### 关键交互规则

- 点击选项即选中，不要二次确认
- 进入下一题时，页面切换应轻量，不要用重动画
- `跳过` 后直接进入下一题，不要再弹确认框
- 第三题答完后，主按钮改为 `查看为你推荐的内容`

### 异常与边界状态

#### 网络提交失败

- Toast：`保存失败，请重试`
- 主按钮恢复可点击

#### 用户中途关闭

- 已回答题目即时保存
- 再次进入时从下一未完成题继续

#### 用户全部跳过

- 允许进入默认首页
- 首页保留轻量补采入口，不做强提醒

## 4. 页面 2：onboarding 完成后的个性化结果页

### 页面目标

让用户立刻看到“我刚才回答的问题，真的换来了更适合我的内容”。

### 线框结构

```text
+--------------------------------------------------+
|                    完成图标                       |
|                                                  |
|   标题：先帮你准备好了这 3 个起步内容            |
|   描述：根据你的目标，我们更推荐你从这里开始      |
|                                                  |
|   [推荐卡片 1：模板]                             |
|   名称 + 简介 + 主按钮                           |
|                                                  |
|   [推荐卡片 2：AI 助手]                          |
|   名称 + 简介 + 主按钮                           |
|                                                  |
|   [推荐卡片 3：引导动作]                         |
|   名称 + 简介 + 主按钮                           |
|                                                  |
|                    [进入首页]                    |
+--------------------------------------------------+
```

### 文案建议

#### 标题

`先帮你准备好了这 3 个起步内容`

#### 描述

`根据你的目标，我们更推荐你从这里开始，这样会更快看到效果。`

### 推荐卡片文案模板

#### 卡片类型 A：模板推荐

- 标题：`项目执行模板`
- 描述：`适合先把项目拆清楚、分好负责人，再开始推进。`
- 按钮：`用这个模板开始`

#### 卡片类型 B：AI 助手推荐

- 标题：`项目拆解助手`
- 描述：`把你的目标告诉我，我可以先帮你拆成任务和节点。`
- 按钮：`让 AI 帮我开始`

#### 卡片类型 C：引导动作推荐

- 标题：`先创建第一个项目`
- 描述：`如果你还没想好模板，也可以直接从空白项目开始。`
- 按钮：`创建空白项目`

### 页面逻辑

- 至少展示 2 张卡片，最多展示 3 张
- 第一张卡片必须与 `primary_scenario` 强相关
- 如果用户选择了 `不知道从哪开始`，优先展示 AI 助手卡片
- 如果用户选择 `老板 / 团队负责人`，优先展示“看板/协作类模板”

### 反馈机制

- 点击任一卡片后，记录 `profile_personalization_clicked`
- 用户点击后进入对应功能，不要再要求重复填写信息

## 5. 页面 3：AI 对话中的补采卡片

### 页面目标

在高意图场景中，以尽量不打断对话的方式补齐关键字段。

### 推荐展示形式

- 作为 AI 消息卡片插入对话流
- 不使用全屏弹窗
- 默认一次只问 1 个问题

### 线框结构

```text
AI：我可以先帮你搭一个项目。

+---------------------------------------------+
| 为了给你更贴近的方案，我想先确认 1 个问题   |
|                                             |
| 你这个项目更偏哪个行业或业务场景？          |
| [互联网] [电商] [制造] [其他]               |
|                                             |
| [先按默认继续]                              |
+---------------------------------------------+
```

### 核心文案规则

- 开头先说明“为什么问”
- 问题必须和当前任务强相关
- 给用户一个明确的“不回答也能继续”的出口

### 文案模板

#### 引导语

`为了给你更贴近的方案，我想先确认 1 个问题。`

#### 问题示例 A：行业

`你这个项目更偏哪个行业或业务场景？`

#### 问题示例 B：团队规模

`这个项目大概会有多少人一起协作？`

#### 问题示例 C：当前工具

`你们现在主要用什么方式跟这个项目？`

#### 次操作按钮

`先按默认继续`

说明：
- 比“跳过”更自然，因为它保留主任务连续性
- 也更符合 AI 对话语境

### 回答后的反馈文案

用户回答后，AI 下一条消息应显式消费答案。

示例：

`明白了，你是电商团队，我先按活动项目来帮你搭一个执行框架。`

这是关键要求。
如果回答完看不出 AI 有变化，用户会觉得这个问题毫无价值。

### 交互规则

- 选项点击后立即提交，不再出现确认按钮
- AI 立刻回一条“已理解”的过渡消息，再给生成结果
- 同一轮会话最多追问一次主问题

### 边界状态

#### 用户选择“先按默认继续”

AI 回复示例：

`可以，我先按通用团队项目来给你搭一个版本，后面你再补充也行。`

#### 用户连续两次拒答

- 本会话不再追问
- 7 天内降低同字段追问优先级

## 6. 页面 4：模板中心触发采集弹层

### 页面目标

在用户点击高意图模板时，用一步补采提升推荐和默认配置准确度。

### 推荐展示形式

- 中央轻弹层
- 不超过 1 个问题
- 可关闭

### 线框结构

```text
+----------------------------------------------+
| 先帮你选个更接近的项目类型                  |
|                                              |
| 你这次更接近下面哪类项目？                  |
| ○ 软件开发                                   |
| ○ 市场活动                                   |
| ○ 客户交付                                   |
| ○ 内部协作                                   |
| ○ 其他                                       |
|                                              |
|                   [跳过] [继续]              |
+----------------------------------------------+
```

### 文案建议

#### 标题

`先帮你选个更接近的项目类型`

#### 问题

`你这次更接近下面哪类项目？`

#### 选项

- `软件开发`
- `市场活动`
- `客户交付`
- `内部协作`
- `其他`

#### 主按钮

`继续`

#### 次按钮

`跳过`

### 交互规则

- 如果用户已明确主场景且近期答过类似问题，不弹
- 选择后进入对应模板列表或带默认参数创建模板
- 跳过后仍允许进入模板，不阻断主任务

### 回答后的反馈

若进入模板详情页，顶部可短暂出现弱提示：

`已为你切到更适合市场活动的模板。`

## 7. 页面 5：首页个性化模块

### 页面目标

把采集后的结果显性地体现在首页，让用户持续感受到“首页是为我配的”。

### 线框结构

```text
+--------------------------------------------------+
| 顶部欢迎语                                       |
| 根据你的目标，今天建议先完成这一步               |
| [主行动按钮]                                     |
|                                                  |
| 为你推荐                                          |
| [模板卡片 1] [模板卡片 2] [AI助手卡片]           |
|                                                  |
| 你可能还需要                                      |
| [补采轻入口：补充行业/团队规模]                  |
+--------------------------------------------------+
```

### 欢迎语文案模板

#### 小团队负责人

`你更像是在推进团队项目，今天建议先把项目拆清楚并分好负责人。`

#### 个人执行者

`你更像是在推进个人事项，今天建议先把事情排成一个能执行的计划。`

#### 企业管理者

`你更关心进度和风险，今天建议先从项目看板或汇总视图开始。`

### 主行动按钮文案

- `开始搭第一个项目`
- `先让 AI 帮我拆任务`
- `查看适合我的模板`

按钮由用户标签决定，不要固定一种。

### 补采轻入口

当字段仍缺失时，首页底部或推荐模块下方可出现一行轻提醒。

示例：

`补充你的行业信息，我们可以推荐更贴近的模板。`

按钮：

`去补充`

说明：
- 这是补采，不是主打断
- 只能轻量出现，不要压主任务

## 8. 页面 6：销售 / 客成补录侧边栏

### 页面目标

让销售/客成在一个侧边栏里看清用户自填信息与企业补录字段，而不是分散在多个表单中。

### 线框结构

```text
+----------------------------------------------+
| 用户上下文                                   |
|                                              |
| 一、用户已填写                               |
| 角色：团队负责人                             |
| 场景：项目管理                               |
| 痛点：进度不可控                             |
| 来源：onboarding / 3天前                      |
|                                              |
| 二、销售补充                                 |
| 公司规模  [下拉]                             |
| 管理成熟度 [下拉]                            |
| 当前工具  [多选]                             |
| 备注      [文本框]                           |
|                                              |
|                [取消] [保存]                 |
+----------------------------------------------+
```

### 文案建议

#### 区块标题

- `用户已填写`
- `销售补充`

#### 字段提示

- `当前管理方式更接近哪种？`
- `客户现在主要用什么工具推进工作？`
- `补充备注（选填）`

### 交互规则

- 用户自填信息默认只读
- 销售填写的信息必须标注来源
- 如果销售字段与用户字段冲突，不在当前页强制判断对错，只允许提交并写入历史

### 保存反馈

Toast：

`已更新客户上下文`

## 10. 交互规则清单

### 必须遵守

- onboarding 单题单屏
- AI 补采一次只问 1 个问题
- 模板触发采集不超过 1 步
- 每次采集后都要给即时反馈
- 所有“跳过”都必须允许继续主任务

### 不建议出现

- “请完善您的信息”
- “提交问卷”
- “为了更好地服务您，请填写以下内容”
- 多个开放题连续出现
- 回答后页面无变化

这些都是典型反模式，因为它们暴露的是业务诉求，而不是用户收益。

## 11. 推荐稿给设计师的补充说明

在视觉上，建议整体偏“轻引导”而不是“强表单”。

具体建议：

- 版面留白要足，让用户感觉只是在回答一个很轻的问题
- 选项卡片可以稍大，优先点按舒适性
- 重点不是装饰感，而是降低认知负担
- 推荐页中的卡片需要有明确主次，第一推荐必须足够突出

不要把 onboarding 做成企业软件式资料填写页。那会直接削弱 PLG 场景下的启动体验。

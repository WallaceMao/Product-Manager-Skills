## One-Paragraph Description

“WPS项目管理“是一个面向 WPS 应用市场平台用户的 AI Native 项目和流程管理助手，帮助个人和小团队从“想法”到“执行落地”一键完成，并通过执行系统实现全流程闭环。在 WPS 体系中，作为 WPS 365 一站式企业协作平台的工作台应用，为用户提供数据执行跟踪和智能化的服务。

### Edition Context

当前产品包含两种主要产品形态：

- **个人版：** 面向 `WPS Office` 用户，以个人开通为主，偏个人任务管理与轻量协作
- **企业版：** 面向 `WPS 365 / 金山协作 / WPS 协作` 客户，以团队或企业开通为主，偏多人协作、项目推进、进度管理与组织级使用

这意味着“WPS 项目管理”虽然是同一产品名，但在用户环境、场景复杂度和能力优先级上可能存在明显差异，后续需要持续验证两者哪些能力应共用，哪些能力应区分版本设计。

## Product Mission

- **产品使命：** 成为 WPS 生态中的执行引擎，让工作从“记录”走向“自动执行”。
- **希望持续创造的核心价值：**
  - 从“不会做项目管理” → “自动帮你做好”
  - 从“想法” → “可执行计划” → “可追踪结果” 一步完成
  - 几乎 0 学习成本（LUI） + 专业能力（GUI）
- **用户为什么应该持续使用它：**
```md
因为它不仅帮助用户“生成项目”，更持续帮助用户“推进执行并获得结果”。

具体表现为：
1. 每次产生新任务或新想法时，用户可以快速通过 AI 转化为可执行项目（持续入口价值）
2. 在项目执行过程中，系统持续提供提醒、跟进、风险识别等能力（执行驱动价值）
3. 所有项目数据、协作记录和复盘沉淀在系统中，形成长期可复用资产（数据沉淀价值）
4. 在多人协作场景中，任务分配与协同依赖该系统完成，形成使用惯性（协作网络效应）

因此，该产品从“工具”转变为“执行系统”，用户离开后将显著增加工作推进成本。
```

## Product Role in WPS Ecosystem

- **在 WPS 体系中的定位：** WPS 项目管理是 WPS 365 生态中的“执行层应用”，承担从内容生产（文档/会议/表单）到任务执行与项目推进的关键转化角色。
- **上游关系：**
  - 文档：项目方案、计划文档 → 生成项目与任务
  - 会议：会议纪要 → 自动提取待办事项
  - 表单：需求收集 → 转化为项目或任务
  - IM / 消息：讨论中的事项 → 结构化为任务
  - 日历：时间安排 → 转化为项目节点或里程碑
  - 通讯录：组织结构 → 自动匹配负责人
- **下游关系：**
  - 项目执行与进度跟踪（任务状态、里程碑）
  - 自动提醒与催办（IM / 通知系统）
  - 汇报与复盘（项目数据、进展报表）
  - 流程触发（审批、流程流转）
  - 数据沉淀（作为组织执行资产）
- **可借力的平台能力：**
  - WPS AI（数字员工 / Agent 能力）
  - 企业通讯录（组织与权限体系）
  - 消息与通知系统
  - 日历与会议系统
  - 云文档与知识库
  - WPS 应用市场分发能力（流量入口）
- **与其他产品的边界：**
  - 不负责内容生产（文档/表格仍在 WPS 中完成）
  - 不替代 IM（沟通仍在消息系统中完成）
  - 不做复杂 ERP / CRM（业务系统仍在外部系统中）
  - 聚焦“执行过程管理”与“任务推进”

### 典型协同链路
1. 用户在 WPS 文档中撰写项目方案
2. 一键生成项目（AI 解析文档 → 生成任务结构）
3. 在项目管理中推进执行（分配任务、跟踪进度）
4. 执行结果通过消息、报表回流到 WPS 体系（IM / 汇报 / 文档）

## Core Value Proposition

从用户视角写出 3 条以内的核心价值主张。

- **价值主张 1：** 帮用户把文档、会议、聊天中的“想法和事项”，一键转化为可执行的项目和任务。
- **价值主张 2：** 帮负责人实时掌握项目进展、风险和阻塞，而不是依赖人工同步和反复追问。
- **价值主张 3：** 帮团队把一次性的项目执行过程沉淀为可复用的模板和流程，持续提升执行效率。

## Target Product Category

- **我们希望用户如何理解这个产品：** AI 驱动的团队执行系统（AI Execution System）
- **用户今天更可能把它当成什么：** 轻量项目管理工具 / 任务协同工具
- **我们希望逐步把认知迁移到什么方向：** 从“项目管理工具” → “AI 执行系统入口（Work Execution OS）”

## Primary Jobs

按“用户想完成什么工作”列出核心任务，而不是功能模块。

### Primary Jobs
1. 发起一个项目，并快速明确目标、任务拆解、负责人和时间节点
2. 在执行过程中持续跟踪进展、识别风险并推动任务完成
3. 将文档、会议纪要和沟通内容转化为结构化任务并持续推进
4. 在多项目场景下进行优先级管理与资源协调
5. 向上汇报项目进展，并在项目结束后进行复盘和沉淀

## Product Scope at a Glance

### In Scope

- 当前明确支持的对象和流程：
  - 项目创建、任务拆解、执行跟踪
  - AI 生成项目与任务
  - 基础协作（任务分配、评论、状态更新）

- 当前已经成熟的关键能力：
  - 项目结构化管理（任务/负责人/时间）
  - 基础 AI 辅助生成
  - 与 WPS 基础能力的初步集成

- 当前服务最稳定的典型场景：
  - 小团队项目协作
  - 轻量项目管理
  - 基于文档/会议的任务生成与跟踪

### Edition Scope Notes

- **个人版当前更适合聚焦：**
  - 个人任务与事项推进
  - 轻量项目跟进
  - 小范围协作
- **企业版当前更适合聚焦：**
  - 团队项目推进
  - 多成员任务协作
  - 进度跟踪与管理汇报
- **当前需要持续验证：**
  - 个人版与企业版是否共享同一产品心智
  - 两个版本是否共享同一能力优先级
  - 哪些能力应保持统一，哪些能力应做版本差异化设计

### Out of Scope or Weak Coverage

- 当前不重点覆盖的场景：
  - 大型企业复杂流程管理
  - 跨系统深度集成（ERP / CRM）
  - 高度定制化项目管理

- 用户经常期待但产品还不擅长的能力：
  - AI 自动推进执行（不仅生成，还能持续驱动）
  - 高级数据分析与预测
  - 跨项目资源优化

- 需要依赖其他系统完成的环节：
  - 沟通（IM）
  - 内容生产（文档/表格）
  - 审批与复杂流程（部分依赖流程系统）

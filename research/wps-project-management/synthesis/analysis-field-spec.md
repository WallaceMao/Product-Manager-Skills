# WPS Demand Analysis Field Spec

这份字段规范用于把原始需求从“表格记录”升级成“可分析、可决策的数据集”。

---

## 原始字段

| 字段 | 含义 |
| --- | --- |
| `edition` | 版本环境：`personal` / `enterprise` |
| `source_file` | 来源文件名 |
| `row_id` | 唯一行 ID |
| `team_name` | 原始团队或企业名称 |
| `demand_text` | 原始需求描述 |
| `level_1` | 一级类目 |
| `level_2` | 二级类目 |

---

## 需要补充的分析字段

| 字段 | 作用 | 建议值 |
| --- | --- | --- |
| `normalized_scenario` | 归一化场景 | 项目创建、任务分工、执行跟进、管理汇报、个人规划、会议转任务等 |
| `user_role_guess` | 推测主要角色 | 个人用户、团队负责人、普通成员、管理者、管理员、不明确 |
| `problem_type` | 问题类型 | 创建困难、信息不清、进度不可见、提醒不足、权限不清、协作成本高、可视化不足等 |
| `request_type` | 需求类型 | 新能力、能力增强、体验优化、AI 能力、数据/报表、集成需求、无法判断 |
| `strategic_relevance` | 当前战略相关度 | 高、中、低 |
| `decision_bucket` | 后续处理建议 | move_to_opportunity_map、validate_first、monitor、reject_or_ignore |
| `data_quality` | 数据质量标记 | valid、weak、invalid |
| `notes` | 分析备注 | 自由填写 |

---

## 推荐的归一化场景

- 项目创建与启动
- 任务拆解与分工
- 执行跟进
- 风险暴露
- 管理汇报与复盘
- 个人规划与日程管理
- 模板化复用
- 会议转任务
- 数据看板与经营分析
- 客户/销售/订单跟进
- 研发项目管理
- 工程与施工项目管理
- 生产制造跟踪
- 其他 / 不明确

---

## 推荐的角色判断口径

- **个人用户**：以个人执行、自我管理为主
- **团队负责人**：负责项目推进、任务分配、进度跟踪
- **普通成员**：承担具体执行任务
- **管理者**：关注整体进展、风险和汇报
- **管理员**：关注开通、权限、组织结构和配置
- **不明确**：文本不足以判断

---

## 推荐的分析口径

### `strategic_relevance`

- **高**：直接关联当前战略主线、must-win 场景、核心留存或扩散
- **中**：有价值，但不是当前主战场
- **低**：边缘需求、噪音需求，或与当前策略不一致

### `decision_bucket`

- **move_to_opportunity_map**：适合进入问题空间与方案设计
- **validate_first**：需求信号存在，但证据不足，需要补访谈或数据
- **monitor**：暂时观察，不进入近期重点
- **reject_or_ignore**：明显无效、噪音、离题或不符合当前策略

---

## 清洗时要特别标记的情况

- `demand_text` 为空或无语义
- 值为 `无`、`1111` 等明显无效输入
- 类目为空
- 描述过短且无法判断
- 多条需求混在一条记录里
- 与产品定义明显无关

---

## 核心原则

- 字段设计的目标不是“分类更细”，而是“让后续产品决策更稳”
- 如果某字段无法稳定判断，先标 `不明确`，不要强行猜
- 优先保证口径一致，而不是一开始追求完美精细

# Demand Insights Summary

这份文档用于从需求数据中提炼真正对产品决策有价值的洞察。

重点不是“哪个类目最多”，而是：

- 哪些问题反复出现
- 哪些问题与高价值角色相关
- 哪些问题与当前战略一致
- 哪些问题值得进入机会池

---

## Executive Summary

- 本轮需求分析最重要的结论 1：
  `WPS 项目管理` 两个版本的共性底座仍然是“项目与任务推进”，这说明产品的核心价值不应从一开始就偏离执行管理主线。
- 本轮需求分析最重要的结论 2：
  个人版和企业版已经表现出明显不同的价值结构。个人版更偏“低门槛启动 + 个人持续推进”，企业版更偏“多人协作 + 进度可见 + 管理可见性”。
- 本轮需求分析最重要的结论 3：
  当前 raw-input 中虽然有大量噪音和泛表达，但已经足够支持第一轮机会识别。下一步不应继续停留在需求统计，而应进入机会筛选和方案设计。

### Data Baseline

- 总需求数：18149
- 第一轮 `valid-only` 样本：13874
- `valid` 占比：76.44%
- `weak + invalid` 占比：23.56%

这意味着：

- 数据足够大，能支持高层方向判断
- 但还不足以直接用“数量排序”做路线图
- 后续需要继续把类目升级成问题空间和场景口径

## Personal Edition Insights

### Top Problem Spaces

1. **项目创建与启动门槛高**
   用户知道自己有事要做，但不擅长把想法、计划、零散事项快速转成可执行项目。
2. **个人执行缺少结构化推进**
   用户不只是想记任务，更想把任务、进度、提醒、阶段安排组织成一个可持续推进系统。
3. **进度跟踪和计划可视化需求强**
   甘特图、时间轴、项目进度、台账等表达频繁出现，说明个人版用户也在寻找“看见进展”的方式。
4. **轻协同和待办提醒需求混入明显**
   个人版不只是单人清单工具诉求，还吸收了小范围协作、提醒、台账和事务跟进需求。
5. **行业表达很多，但底层问题常常相似**
   工程、制造、研发等行业场景占比很高，但底层问题大多仍然围绕计划、推进、分工和可见性。

### Key Signals

- 高频角色：
  - 个人用户
  - 轻量项目发起者
  - 小团队负责人（但更多以个人视角表达）
- 高频场景：
  - 项目创建与启动
  - 个人规划与日程管理
  - 项目进度跟踪
  - 轻量任务协同
- 主要痛点类型：
  - 不知道怎么拆任务
  - 事项多且容易乱
  - 缺少清晰进度视图
  - 工具太重或配置成本太高
- 对激活 / 留存最敏感的信号：
  - 是否能快速把想法转成结构化项目
  - 是否能让用户持续管理自己的事项和计划
  - 是否能提供足够轻量但不空洞的推进体验

### Current Interpretation

个人版最值得重视的，不是“功能是否够全”，而是：

- 是否有明确的低门槛启动能力
- 是否有持续推进的个人执行价值
- 是否能避免滑向“只是另一个待办工具”

其中 `个人规划与日程管理` 是最值得单独跟踪的独有信号，但目前还不能直接断言它就是个人版的唯一主战场，仍需要结合留存和转化数据验证。

## Enterprise Edition Insights

### Top Problem Spaces

1. **执行跟进成本高**
   团队负责人需要频繁问人、开会、手工维护台账，才能知道项目推进情况。
2. **任务拆解与分工协作不顺**
   企业版需求大量集中在项目计划、任务分工、负责人和节点管理，说明团队协作进入执行阶段时仍很吃力。
3. **进度可视化与管理可见性不足**
   甘特图、进度跟踪、时间节点提醒、管理视图等需求频繁出现，说明企业版用户需要的不只是记录，而是可管理的执行状态。
4. **重执行行业场景非常强**
   工程、施工、制造、研发等行业信号明显，说明企业版用户需求更偏“过程推进系统”而不是泛协同工具。
5. **经营与汇报视角开始出现，但不是主起点**
   数据分析与经营看板类需求存在，但当前更像对执行过程结果的延伸需求，而不是第一性价值。

### Key Signals

- 高频角色：
  - 团队负责人
  - 项目 Owner
  - 多成员协作团队
  - 管理者 / 观察者
- 高频场景：
  - 执行跟进
  - 任务分工
  - 项目计划与排期
  - 进度管理与汇报
- 主要痛点类型：
  - 状态不可见
  - 需要反复催人
  - 节点和负责人不清
  - 项目过程难以可视化
- 对协作深度 / 留存 / 管理价值最敏感的信号：
  - 是否能减少负责人手工跟进成本
  - 是否能让团队成员进入更清晰的协作节奏
  - 是否能让管理视角看到真实进展和风险

### Current Interpretation

企业版更像在验证：  
`WPS 项目管理` 能不能成为团队执行系统，而不是只做一个记录工具或轻量任务板。

从当前数据看，企业版的主战场不是“个人生产力”，而是：

- 团队推进
- 进度可见
- 多角色协作
- 管理视角下的执行透明度

## Shared Foundations vs Edition-Specific Needs

### Shared Foundations

- 项目与任务管理是绝对共性底座
- 进度跟踪和计划管理是两边都高频的核心需求
- 可视化表达（甘特图、时间轴、进度表）在两边都反复出现
- 用户都在寻找“更低成本的执行推进方式”，而不仅是记录功能

### Personal-Only or Personal-First

- 个人规划与日程管理
- 轻量、快速、低配置启动
- 将日常工作、计划、日志、提醒组织成个人执行系统
- 小范围协作，但不希望引入企业级复杂度

### Enterprise-Only or Enterprise-First

- 多人协作下的任务拆解与分工
- 团队负责人视角下的执行跟进
- 管理和汇报视角下的进度可见性
- 工程、制造、研发等重执行场景的过程控制

### Strategic Implication

当前不适合默认“个人版和企业版只是 UI 不同”。  
更合理的理解是：

- 两者共享一部分执行底座能力
- 但在价值主张、主场景、成功指标上已经出现明显分化

## Noise and Distortion Risks

- 明显无效或低价值需求类型：
  - `无`
  - 空类目
  - 数字占位
  - 极短且无语义表达
- 容易被高频但低价值需求带偏的区域：
  - 视图类表达，例如甘特图、横道图、看板
    - 这些往往是更深层问题的表面语言，不应直接等同于功能优先级
  - 台账类表达
    - 其中很多其实是在表达“跟踪与可视化”问题
- 容易被大客户表达绑架的区域：
  - 工程、施工、制造等行业型需求
    - 它们很重要，但不能自动推导出“产品必须行业化”
  - 经营看板和复杂报表
    - 可能会把产品带向 BI 或重管理系统，而偏离执行主线

### Current Risk Assessment

当前最大的误判风险不是“需求太少”，而是：

- 把类目当问题
- 把功能词当机会
- 把行业标签当产品战略

---

## Recommended Product Implications

- 对战略的启发：
  - `WPS 项目管理` 的共性底座仍然应围绕执行推进展开
  - 企业版应优先围绕“团队执行系统”价值做判断
  - 个人版应优先围绕“低门槛启动 + 持续推进”做判断
- 对方案设计的启发：
  - 第一批方案不应从“补所有视图”开始
  - 更应该围绕：
    - 如何更快启动项目
    - 如何更清楚分工
    - 如何更低成本看见进展和风险
- 对 PRD 范围控制的启发：
  - 每份 PRD 必须明确 edition
  - 必须说明主要角色和场景
  - 必须说明它解决的是哪个问题空间，而不是只写功能描述
- 对季度规划的启发：
  - 当前最值得进入 bet 讨论的方向是：
    - 企业版执行跟进与风险可见性
    - 企业版任务拆解与分工协作
    - 个人版项目创建与启动

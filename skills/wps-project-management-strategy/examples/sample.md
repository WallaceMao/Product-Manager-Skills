# Sample: WPS Project Management Strategy Brief

```markdown
# WPS Project Management Strategy Brief

## 1. Strategic Problem
WPS Project Management must decide whether near-term success depends more on broad personal edition activation or on enterprise edition team execution depth. This matters because both paths demand different scenarios, metrics, and product tradeoffs.

## 2. Product Context
- Current stage: 0-to-1 PMF validation
- Personal edition role: lightweight execution intake for WPS Office users
- Enterprise edition role: team execution and progress visibility inside WPS 365

## 3. Primary Focus
- Primary user environment: Enterprise edition
- Primary segment: Team lead / project owner in small-to-mid collaboration teams
- Must-win scenarios:
  - Turn document or meeting output into shared execution
  - Assign and track work without heavy setup
  - Keep progress visible without constant manual chasing

## 4. Strategic Position
Own the execution layer between WPS content creation and real delivery.

## 5. Differentiation
Unlike generic project tools, WPS Project Management can start from native office artifacts and convert them into executable work with lower setup friction.

## 6. Adoption Path
- Entry point: document, meeting, or idea becomes a project draft
- Aha moment: a team lead sees structured tasks appear with almost no setup
- Repeat loop: status updates, reminders, and follow-through keep work moving
- Expansion path: one owner invites a team and begins recurring execution inside the same system

## 7. Non-Goals
- We will not optimize for large-enterprise custom process complexity
- We will not chase every competitor feature
- We will not assume personal edition needs the same depth as enterprise edition
```

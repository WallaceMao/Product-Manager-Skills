# User Segments

## Purpose

这份文档用于定义和统一目标用户分层，回答：

- 谁在使用这个产品
- 谁决定是否采用
- 谁在推动组织内落地
- 各类角色的目标、痛点、行为差异是什么

这不是画像装饰文档。用户分层的价值在于帮助后续做战略聚焦、功能设计和方案取舍。

---

## Segmentation Logic

先写清楚你是按什么方式划分用户，而不是直接罗列人群。

- **主要划分维度：**
  - 团队规模（个人 / 小团队 / 企业）
  - 协作复杂度（个人任务 → 跨人协作 → 跨部门协作）
  - 使用场景（轻量项目 / 日常任务 / 流程驱动）
  - 使用动机（自我管理 / 团队协作 / 管理控制）
- **为什么采用这组维度：** 本产品的核心差异在于“执行复杂度”和“协作深度”，而不是行业差异。同时，PLG 模式决定了用户往往从个人或小团队起步，因此团队规模和协作复杂度是最关键的分层依据。
- **当前不采用哪些维度：**
  - 行业（当前需求高度通用）
  - 付费能力（尚未进入商业化深水区）
  - 公司规模（早期更关注使用行为而非组织属性）

### Edition-Level Context

当前产品至少存在两类一级用户环境，这会直接影响后续用户分层、场景优先级和功能判断：

- **个人版环境：**
  - 以 `WPS Office` 用户为主
  - 通常由个人开通
  - 更偏个人任务管理、个人执行和轻量协作
- **企业版环境：**
  - 以 `WPS 365 / 金山协作 / WPS 协作` 客户为主
  - 通常以团队或企业身份开通
  - 更偏团队协作、项目推进、权限管理和管理视角

这意味着用户分层不能只按“角色”来做，还要先区分用户处于哪种产品环境中。否则很容易把个人用户和企业团队用户混在一起，导致需求判断失真。

## Segment Detail


### Segment A：个人执行者

- 角色定义：以个人为单位进行任务和项目管理的人
- 典型职位/身份：内容创作者、产品经理、运营、自由职业者
- 所处组织环境：弱组织或自我管理
- 团队规模：1人
- 他们为什么会接触到这个产品：
  - 在 WPS 中写文档 / 计划
  - 想把想法转成行动

#### Goals
- 把想法快速变成可执行计划
- 管理个人任务，避免遗漏
- 提高执行效率

#### Main Jobs
- 创建个人项目（如写文章、做活动）
- 拆解任务并安排时间
- 跟踪进度

#### Pain Points
- 想法很多，但难以落地
- 使用 Excel / 备忘录管理混乱
- 项目管理工具太复杂

#### Behaviors
- 常用工具：WPS、Notion、备忘录
- 偏好轻量、快速上手
- 不愿意做复杂配置

#### Triggers
- 有一个新想法或项目
- 工作变复杂，开始混乱

#### Buying / Adoption Role
- 使用者 + 决策者

#### Success Criteria
- 能否 1 分钟内生成可执行计划
- 是否减少思考成本

#### Risks / Friction
- 如果 AI 不够好 → 直接流失
- 如果操作复杂 → 不再使用

#### Representative Quotes
- “我只是想把这件事理清楚，不想学工具”
- “有没有能帮我自动拆任务的工具？”

### Segment B：小团队负责人（⭐核心）

- 角色定义：项目发起者和推进者
- 典型职位/身份：团队负责人、项目经理、创业团队负责人
- 所处组织环境：小团队，流程不完善
- 团队规模：2–10人
- 他们为什么会接触到这个产品：
  - 在 WPS 中做项目方案 / 会议
  - 需要推动团队执行

#### Goals
- 快速发起项目并分配任务
- 持续跟进进展
- 保证项目按时完成

#### Main Jobs
- 项目拆解与分工
- 跟进进度与催办
- 汇报结果

#### Pain Points
- 需要频繁催人
- 项目状态不透明
- 依赖开会同步

#### Behaviors
- 常用工具：Excel、飞书、微信群
- 强依赖沟通推动执行
- 时间碎片化

#### Triggers
- 项目延期
- 团队协作混乱
- 管理成本上升

#### Buying / Adoption Role
- 使用者 + 推动者 + 决策者（核心）

#### Success Criteria
- 是否减少沟通成本
- 是否让项目更可控
- 是否减少“盯人”

#### Risks / Friction
- 团队不配合使用
- 工具增加额外负担

#### Representative Quotes
- “我每天都在问进度，很累”
- “有没有不用催也能推进的工具？”

### Segment C：团队成员
- 角色定义：执行具体任务的人
- 典型职位/身份：普通员工
- 团队规模：2–10人

#### Goals
- 清楚知道自己要做什么
- 高效完成任务

#### Pain Points
- 信息分散（群聊/口头）
- 优先级不清

#### Behaviors
- 被动接收任务
- 不主动使用工具

#### Buying / Adoption Role
- 使用者（被动）

#### Success Criteria
- 是否清晰、简单
- 是否减少沟通

#### Risks / Friction
- 觉得麻烦 → 不用

### Segment D：企业管理者
- 角色定义：关注整体项目情况的人
- 典型职位：部门负责人 / CEO

#### Goals
- 了解项目进展
- 控制风险

#### Pain Points
- 信息滞后
- 数据不透明

#### Buying / Adoption Role
- 决策者

#### 当前问题
- 当前产品对其价值不足（偏执行层）

## Priority Segments

### Primary Segment

- **是谁：** 小团队负责人（Segment B）
- **为什么优先：**
  - 同时具备“强需求 + 决策权 + 推动力”
  - 能带来团队扩散（PLG 核心）
- **当前机会：** WPS 场景中有大量“轻量项目负责人”
- **当前风险：** 团队不跟随使用 → 产品失效

**当前需要额外回答：**

- 个人版和企业版是否应分别定义 Primary Segment
- 当前阶段优先服务个人版增长，还是优先服务企业版团队协作
- 两个版本是否共享同一套“核心用户”定义

### Secondary Segment

- **是谁：** 个人执行者（Segment A）
- **为什么次优先：** 易激活，但扩散能力弱
- **什么时候值得投入：** 当需要扩大用户规模时

### Deferred / Non-Core Segment

- **是谁：** 企业管理者（Segment D）
- **为什么暂时不优先：** 当前产品能力无法满足其复杂需求

## User Role Map

如果产品涉及多人协作，建议明确不同角色的关系。

| Role | 是否直接使用 | 是否高频使用 | 是否影响采购/上线 | 主要关注点 |
| --- | --- | --- | --- | --- |
| 个人版个人用户 | 是 | 是 | 是（个人决策） | 上手成本、个人执行效率、轻量管理 |
| 企业版团队负责人 | 是 | 是 | 是 | 分工推进、进度可见性、团队协作效率 |
| 企业版普通成员 | 是 | 是 | 否 | 接任务清晰、协作顺畅、提醒及时 |
| 企业版管理者 / 决策者 | 视情况 | 低 / 中 | 是 | 全局视图、风险暴露、汇报效率 |
| 企业版管理员 / IT | 视情况 | 低 / 中 | 是 | 开通、权限、组织管理、配置成本 |
| 项目负责人 | 是 | 是 | 是 | 进度、可控性 |
| 普通成员 | 是 | 中 | 否 | 清晰、简单 |
| 团队管理者 | 否/低 | 低 | 是 | 汇报、风险 |
| 管理员 / IT | 否 | 低 | 中 | 集成、权限 |
| 企业决策者 | 否 | 低 | 是 | ROI |

## Segment Comparison

- 最在意轻量上手：个人执行者
- 最在意执行推进：小团队负责人
- 最在意清晰任务：团队成员
- 最在意数据与控制：企业管理者
- 最容易带来扩散：小团队负责人
- 最容易误导产品方向：企业管理者（需求复杂、偏系统化）

## Evidence Base

- 销售 / 客服反馈：轻量协作需求强
